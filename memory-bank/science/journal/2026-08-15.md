# Journal Science — 2026-08-15

## Plan A4-5 — Export des états thermodynamiques par itération

**Agent** : PATCHER
**Objectif** : `resultats.etats_par_iteration` conserve les états des N cycles
réellement résolus par la campagne (jusque-là jetés dans `_run_chunk()`), sans
toucher au cycle nominal `resultats.etats_cycle` qui alimente les diagrammes T-s.

### Modifications

1. **`backend/app/engine/monte_carlo.py`** :
   - `_run_chunk()` : nouveau paramètre `collecter_etats: bool = False`,
     propagé à `run_cycle(..., include_states=collecter_etats)`. Collecte
     `{"iteration": rang_local, "states": ...}` pour chaque tirage retenu,
     retournée dans `etats_par_iteration`.
   - `run_campaign()` : nouveau paramètre `collecter_etats` (position après
     `sorties_suivies`, avant `progress_cb`/`N_sobol` — non cassant, tous les
     appelants existants utilisent des kwargs ou s'arrêtent à 3 positionnels).
     Rebasage de l'index `iteration` à la fusion des chunks parallèles
     (offset = nombre de tirages retenus déjà accumulés) pour éviter les
     doublons d'index entre chunks. Chemin séquentiel (< `PARALLEL_THRESHOLD`)
     et chemin parallèle tous deux couverts.
   - `resultats.etats_par_iteration = etats_tous` — vide si flag désactivé.

2. **`backend/app/schemas/reporting.py`** :
   - `Resultats.etats_par_iteration: list[dict] = []` (nouveau champ).
   - `CampagneRequest.collecter_etats: bool = False` (nouveau champ, pour
     activation via l'API).

3. **`backend/app/engine/runner.py`** et **`backend/app/api/routes/circuits.py`** :
   propagation du flag `POST /api/{circuit}/run` → `runner.start_run()` →
   `run_campaign()`. Hors périmètre initial (2 fichiers annoncés) mais requis
   par la spec §4 de la demande pour que le champ `CampagneRequest.collecter_etats`
   ne soit pas mort ; changement minimal, rétrocompatible (défaut `False`).

4. **`backend/tests/test_etats_par_iteration.py`** (nouveau, 6 tests) :
   désactivé par défaut, nombre d'états = nombre de tirages retenus, index
   contigu 0..N-1 après fusion parallèle (N=500), variation des états entre
   itérations, cohérence état 8 vs `T_g` tiré, invariant Δh_gen par itération.

### Résultats

- **Tests** : `pytest backend/tests/test_etats_par_iteration.py -v` → 6/6 verts.
  Suite complète : 56/56 verts (aucune régression).
- **Régression numérique (N=500, seed=42)** : statistiques bit-identiques
  avec/sans `collecter_etats` (le flag ne change aucune valeur physique).
  Cycle nominal inchangé : `h_7=146.740` · `h_8=2667.614` · `Δh=2520.874 kJ/kg`.
  `COP × Q_gen = 11.9995` (invariant A4-2 intact).
- **Livrable §7 de la demande** : campagne N=500 seed=42 `collecter_etats=True`
  exportée en CSV (format long, 4000 lignes = 500×8) via script ad-hoc — aucun
  export CSV n'existe dans ce repo (l'API ne produit que du JSON via Redis) ;
  md5 du nouveau `_cycle.csv` = `b142046ce2fb29ccacbedd6d12525c2b`, différent
  de l'ancien md5 figé `de03c87ee6505fcf22bba71d0cddce1f` — confirme la
  correction du bug (les états varient désormais bien entre itérations).
